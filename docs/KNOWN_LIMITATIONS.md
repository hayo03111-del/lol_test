# 알려진 한계

이 문서는 "구현했지만 실제 LoL과 다르게 근사한 부분"과 "아예 구현하지
않고 의도적으로 건너뛴 부분"을 한곳에 모은다. 전부 각 기능을 구현할 때
남긴 코드 주석/README 서술에서 가져온 것이고, 이 문서를 쓰면서 새로
지어낸 내용은 없다.

## 1인용 데모라는 근본적 한계

이 엔진에는 아군 챔피언, 소환사 주문, 정글 캠프 같은 실제 LoL의
멀티플레이·메타 요소가 전혀 없다. 이로 인해 다음 효과들이 영향을 받는다:

- **꿈 생성기(dreamMaker)**: "다른 아군에게 체력을 회복시키거나
  보호막을 씌우면" 효과를 얻는 서포터 아이템인데, 아군이라는 개념
  자체가 없어 핵심 패시브를 구현할 방법이 없다. 스탯과 와드 설치
  기능만 제공하고, 고유 패시브는 **의도적으로 미구현** 상태다
  (`src/champions/item_data.js`의 `dreamMaker` 항목 참고 - 다른
  업그레이드와 달리 고유 패시브 필드가 아예 없다).
- **세계지도집/룬나침반의 "아군 챔피언 근처에서"**: 재물 공유(골드 획득)
  조건에 있는 "아군 챔피언 근처"는 플레이어 자신이 항상 자기 자신과
  "가까이" 있는 것으로 근사해, 조건 없이 항상 발동하는 것으로 처리했다.
- **강철의 솔라리 팬던트(ironSolariLocket)**: "헌신"(주변 아군들에게
  보호막)이 핵심 패시브인데, 월석재생기와 달리 "아군이 없으면 자신에게
  적용"처럼 자기 대상으로 전환하는 조항이 원문에 전혀 없다 - 이 데모에
  아군이 아예 없는 이상 조건을 만족할 대상 자체가 없어 고유 패시브를
  **의도적으로 미구현** 상태로 뒀다(`src/champions/item_data.js`의
  `ironSolariLocket` 항목 참고 - 스탯만 제공한다).
- **슈렐리아의군가/밴들파이프의 "주변 아군"**: 사용 시 이동속도 버프
  (슈렐리아의군가)와 CC 적중 시 이동·공격속도 버프(밴들파이프)가 원문상
  "주변 아군"(밴들파이프는 "자신을 포함한")에게 적용되는데, 이 데모는
  자신에게만 적용한다 - 자신 몫은 원문 그대로 정확히 재현되고, 다른
  아군에게 나가는 부분만 관찰 불가능한 생략이다.
- **월석재생기의 "별빛 은총"**: "아군에게 돌아가는 회복/보호막을 다른
  아군에게 재분배, 근처에 아군이 없으면 같은 대상(자기 자신)에게 적용"
  이라는 원문 조항 중, 이 데모는 아군이 없어 후자(자기 대상) 조항이
  "항상" 성립한다 - 자신에게 걸리는 회복/보호막이 30%/35% 증가하는
  것으로 정확히 근사했다(재분배 자체는 관찰 불가능해 생략).
- **제국의명령의 "통제"**: "이동 불가 효과를 지닌 스킬의 스킬 가속이
  20 증가"는 어떤 스킬이 "이동 불가"를 거는지 챔피언마다 따로 태그하는
  시스템이 없어 구현하지 않았다(명령만 구현 - 아래 참고).

## 스킬/평타 구분이 불가능해서 생긴 근사

이 엔진은 "피해의 출처가 스킬인지 평타인지"를 일부 경로에서 세밀하게
구분하지 못한다. 이로 인해:

- **무효화 패시브(`nullifyPassive`, 신록의 장벽/벤시의장막)**: 원래는
  "적의 다음 스킬 피해를 막는 주문 방어막"이지만, 이 엔진에서는 "다음
  피해 1회를 종류 무관하게 전부 차단"으로 근사했다.

## 범위(AoE) 타겟팅의 근사

광역 추적 시스템이 따로 없는 엔진이라, 여러 아이템의 "범위 내 전체"
효과가 "현재 선택한 단일 대상 기준"으로 근사돼 있다:

- **강철심장의 "거인의 흡수"**: 원래는 700 사거리 내 챔피언 전체를
  대상으로 충전이 진행돼야 하지만, `ctrl.currentTarget`이 사거리 내
  챔피언인 동안만 진행되는 것으로 근사했다.

## 수치 원문 누락 → 실제 LoL 수치 사용(`*Guessed`/`apSourceWiki` 플래그)

원문 자료에 가격/반경/지속시간 수치가 빠져 있던 항목은, 자체적으로 수를
지어내지 않고 실제 LoL의 공개 수치를 가져와 썼다 - `item_data.js`에서
해당 필드 옆에 `priceGuessed`/`radiusGuessed`/`durationGuessed`/
`apSourceWiki` 같은 플래그로 출처를 명시해 뒀다. 대표적으로:

- 라바돈의 죽음모자의 자체 주문력 수치(130) - 원문에 패시브/조합 비용은
  있었는데 정작 스탯 줄만 누락돼 있었음(`apSourceWiki: true`).
- 원기 회복의 구슬/천갑옷/B.F. 대검 등 몇몇 기본 아이템의 가격
  (`priceGuessed: true`).
- 여러 AoE 패시브(끝없는 절망의 고뇌, 자자크의 세계가시의 공허 폭발,
  천상의 이의의 충격파 등)의 반경(`radiusGuessed: true`)과 일부
  지속시간(`durationGuessed: true`) - 원문에 효과는 있지만 정확한
  수치가 없어 LoL 실제 값으로 채웠다.

## 흡혈/회복 보너스가 모든 회복 경로를 덮지 못함

- **정령의형상(무한한 활력, "받는 모든 체력 회복·보호막 +25%")**: 공용
  회복 경로(기본 재생, HoT 큐, 물리/모든 피해 흡혈, 생명선 보호막 4종)
  에는 적용했지만, 챔피언마다 개별 구현된 자체 회복 스킬(예: 각 챔피언
  고유 패시브/스킬의 회복량 계산)까지는 전부 손대지 못했다.

## 시각 효과만 영향받고 실질적 차이가 없는 경우

- **유체화(`ghostingPassive`)**: "이동 시 미니언·챔피언과 충돌하지
  않음" 효과인데, 이 데모 자체에 유닛 간 충돌 판정이 없어 켜져 있든
  꺼져 있든 실질적인 차이가 없다.

## 과거에 실제로 있었고 고친 버그(참고용 - 더 이상 유효하지 않음)

- **마법사의 최후(witsEnd)의 잘못된 하위템**: 음전자 망토 대신
  마법무효화의 망토를 하위템으로 쓰고 있었다 - 완제품 스탯 자체는
  우연히 맞았지만 조합 비용/상점 표시가 틀려 있었다. 수정 완료
  (README "전설급 아이템 9차분" 섹션 참고).
- **스펠블레이드(주문 검) 6종의 "기본 공격력" 계산 오류**: 삼위일체/
  정수약탈자/황혼과새벽/리치베인/피의 노래와, 주문 검은 아니지만 같은
  패턴을 쓰던 바다의 지휘관의 모자/신성한 분리자까지 총 6곳이
  "기본공격력"(아이템 보너스 제외)을 요구하는데 "총 공격력"(아이템
  보너스 포함)을 곱하고 있었다 - 공격력 아이템을 더 살수록 피해가
  부풀려지는 버그였다. 수정 완료(README "QA 재점검 3" 섹션,
  `tests/spellblade_base_ad_audit_test.js`로 회귀 방지).
- **상점 상세 설명(툴팁)에 누락된 패시브 설명 다수**: 실제 로직은
  구현돼 있는데 상점 설명 생성 함수(`_itemStatsSummary`)가 새로
  추가된 필드를 몰라 설명이 비어 있던 경우가 여러 차례 있었다(가장
  최근엔 서포터 아이템의 `questPassive`/`spoilsOfWarPassive`/
  `goldPerIntervalPassive`/`voidBurstPassive`/`ccTriggerPassive`/
  `mountainsBlessingPassive`, 그리고 `maxCharges` 기반 와드의 "최대
  undefined개 소지" 표시 버그). 해당 함수는 새 패시브 필드를 추가할
  때마다 설명도 같이 추가해야 한다는 걸 잊기 쉬운 지점이다 - 새 아이템을
  추가할 때는 상점에서 직접 상세 패널을 열어 설명이 비어 있지 않은지
  확인하는 걸 권장한다.
- **인벤토리 슬롯 클릭 시 사용 대신 판매되는 버그**: 인벤토리 슬롯을
  클릭했을 때 사용(`useItem()`)할지 판매(`sellItem()`)할지를 가르는
  `global_system_instances.js`의 `usable` 판정이 `consumable`/
  `activeAbility`/`wardPlacement`/`elixirEffect` 네 필드만 확인하고
  있었는데, `useItem()` 자신의 분기 목록에는 `empoweredCleaveActive`/
  `shockwaveActive`/`ghostStepActive`/`rocketbeltActive`/
  `noxiousBladeActive`/`stasisActive`도 있었다 - 이런 액티브 아이템을
  인벤토리에서 "클릭"하면 사용이 아니라 판매가 되는 버그였다(숫자
  단축키로는 정상 동작해 지금까지 드러나지 않았다). 수정 완료(README
  "하위/상위 아이템 시스템 점검" 섹션 참고).
