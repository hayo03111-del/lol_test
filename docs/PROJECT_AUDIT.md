## 이번 라운드에서 발견한 버그

### 1. 스펠블레이드(주문 검) 6종의 "기본 공격력" vs "총 공격력" 오류

원문을 "기본공격력"/"기본 공격력"으로 전수 재검색한 결과, 아래 6개
지점이 전부 "기본" 공격력(아이템으로 늘어난 보너스 제외)을 요구하는데
실제로는 아이템 보너스가 반영된 "총" 공격력을 곱하고 있었다 -
공격력 아이템을 더 살수록 이 아이템들의 추가 피해까지 같이 부풀려지는
밸런스 버그였다.

- 삼위일체(trinityForce) - "기본 공격력 200%"
- 정수약탈자(essenceReaver) - "기본공격력 125% + 63%"
- 황혼과새벽(duskAndDawn) - "기본공격력 75%"
- 리치베인(lichBane) - "기본공격력 75%"
- 피의 노래(bloodsong, 신규) - "기본공격력 100%"
- 바다의 지휘관의 모자(hullbreaker)의 "선장" 패시브, 신성한 분리자
  (divineSunderer)의 "라이트쉴드 타격" 패시브(둘 다 주문 검은 아니지만
  동일한 "기본공격력" 요구 + 동일한 버그 패턴)

**수정**: 이미 스테락의도전/마나무네가 쓰던 `computeChampionStats(championId,
champLevel)`로 레벨별 기본 스탯을 다시 조회하는 방식을 6곳 전부에
적용했다. 레벨 1/레벨 18에서 기대값이 달라지는지(레벨 의존 조회가
실제로 동작하는지), 공격력 아이템을 추가로 사도 보너스가 그대로인지
(총 공격력 오염 제거 확인) 둘 다 검증하는 전용 회귀 테스트
(`tests/spellblade_base_ad_audit_test.js`)를 새로 추가했다.

### 2. 상점 상세 설명(툴팁)에서 7개 패시브 설명 누락 + 와드 표시 버그

`_itemStatsSummary()`(상점 상세 패널의 설명 텍스트를 만드는 함수)가
새로 추가된 패시브 필드들을 몰라, 실제 로직은 전부 동작하는데도 상점
설명에는 아무것도 뜨지 않고 있었다(플레이어 입장에서는 "효과가 안
걸리는 것 같다"고 오해하기 쉬운 상태):

- `questPassive`, `spoilsOfWarPassive`, `goldPerIntervalPassive`,
  `voidBurstPassive`, `ccTriggerPassive`, `mountainsBlessingPassive`
  (전부 신규 서포터 아이템 패시브)
- 스펠블레이드의 `exposeWeaknessPassive`(피의 노래의 "약점 노출")
- `wardPlacement` 설명이 `item.maxStack`만 읽어서, `maxCharges` 기반
  와드(세계의 결실 계열)에서 "최대 **undefined**개 소지"로 표시되던
  버그

전부 `src/core/global_system_instances.js`의 `_itemStatsSummary()`에
설명 생성 로직을 추가/수정해 해결했다.

## 신규 구현: 서포터 아이템 라인

원문 79~128줄(세계지도집/룬나침반) + 1290~1362줄(세계의 결실 + 업그레이드
5종)을 반영했다. 퀘스트 변신 체인(세계지도집 → 400골드 → 룬나침반 →
800골드 → 세계의 결실), 재물 공유(충전 기반 전투/처형 골드 수급, 65초
첫 충전 게이트), 10초당 골드, 그리고 5종 업그레이드(자자크의 세계가시
- 공허 폭발, 피의 노래 - 주문 검+약점 노출, 태양의 썰매 - CC 적중 트리거
회복+이속, 천상의 이의 - 피해 감소+만료 시 충격파, 꿈 생성기 - 아군
의존 메커니즘이라 의도적 미구현)까지 전부 구현했다. 자세한 메커니즘은
README의 "QA 재점검 3" 섹션, 구현하지 않은 부분은
`docs/KNOWN_LIMITATIONS.md` 참고.

## 검증 방법과 그 한계

- **단위 테스트**: `tests/run_all.js` - Node `vm`으로 실제 `src/*.js`를
  로드해 실제 함수를 호출하는 방식(모킹/재구현 없음). 25개 파일, 약
  1,700개 assert, 전부 통과. 상세는 `docs/TESTING.md`.
- **빌드 동기화 검증**: `tools/check_build.py` - manifest 파일 존재,
  `dist/runtime.js` 문법, `index.html`의 embedded-runtime 블록이
  `dist/runtime.js`와 실제로 일치하는지, import map과 핵심 DOM 컨테이너
  존재 여부를 확인. PASS.
- **헤드리스 Chromium 스모크 테스트**: 실제 `index.html`을 로컬 서버로
  띄우고 Chromium으로 열어 상점 탭 전환·아이템 클릭·상세 패널 표시를
  검증(콘솔 에러 0건). 이 테스트 자체는 Playwright 의존성 때문에
  `tests/`에는 커밋하지 않았다(`docs/TESTING.md` 참고).
- **하지 않은 것(솔직하게 명시)**: 이 라운드는 "서포터 아이템 + 버그
  확인 + 주문 검 검증"이라는 범위에 집중했다. 다음은 수행하지 않았다 -
  (1) 프로젝트 전체 149개 아이템 / 17개 챔피언의 모든 상태 변수에 대한
  전수 메모리 누수·타이머 정리 감사(과거 세션에서 발견된 개별 버그들은
  README의 해당 라운드 섹션에 기록돼 있지만, 이번 라운드에서 전체를
  다시 훑지는 않았다), (2) 실제 브라우저에서 사람이 플레이하며 체감
  밸런스를 확인하는 수동 플레이테스트, (3) 챔피언별 스킬 로직(아이템
  시스템 밖)에 대한 재검증. 이 세 가지는 범위 밖임을 명시해 둔다 -
  "전부 확인했다"고 과장하지 않는다.
