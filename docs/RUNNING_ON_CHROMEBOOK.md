# Chromebook(크롬 브라우저)에서 실행하기

이 프로젝트는 별도 설치 프로그램이나 Windows 전용 실행 파일이 필요 없다 -
`index.html` 하나를 크롬 브라우저로 열면 된다. 다만 아래 두 가지 외부
의존성은 반드시 알아둬야 한다.

## 1. 인터넷 연결이 필요하다(오프라인 실행 불가)

`index.html`은 Three.js(및 GLTFLoader/SkeletonUtils/CSS2DRenderer)를 전부
`cdn.jsdelivr.net`에서 내려받는다(`index.html`의 `<script type="importmap">`
블록 참고). **게임 로직 자체(아이템/스킬/상점)는 전부 `index.html` 안에
내장돼 있어 추가 파일이 필요 없지만, 렌더링 라이브러리(Three.js)는
매번 인터넷에서 받아온다** - 즉 완전한 오프라인 실행은 지원하지 않는다.
학교 Chromebook처럼 방화벽이 있는 네트워크에서는 `cdn.jsdelivr.net`
접속이 막혀 있지 않은지 먼저 확인한다.

## 2. 챔피언 3D 모델(GLB 파일)은 이 저장소에 포함돼 있지 않다

`assets/` 폴더에는 일부 챔피언의 VFX 텍스처(이미지)만 들어 있고, 실제
3D 모델 파일(.glb)은 저장소에 전혀 포함돼 있지 않다(용량 문제로 별도
배포). 챔피언을 실제로 움직이거나 스킬을 쓰려면, 화면의 GLB 업로드
버튼(또는 드래그 앤 드롭 영역)에 가지고 있는 `.glb` 파일을 직접
불러와야 한다 - GLB 파일이 없으면 상점/아이템 UI는 열리지만 캐릭터
자체는 뜨지 않는다. **이 문서는 GLB 파일을 어디서 구하는지는 안내하지
않는다(저장소가 제공하지 않는 외부 애셋이기 때문)** - 가지고 있는 파일을
그대로 쓰면 된다.

## 3. 실행 방법

### 방법 A - 그냥 더블클릭해서 열기(`file://`)
`index.html`을 파일 관리자에서 더블클릭하거나 크롬 주소창에
`file:///경로/index.html`로 입력해서 연다. 게임 로직이 전부 파일 하나에
내장돼 있어(위 "HTML 런타임과 빌드 파일 동기화" 구조 참고) 로컬 서버
없이도 대부분 그대로 동작한다 - 다만 위 1번 항목(CDN 인터넷 연결)은
`file://`로 열어도 여전히 필요하다.

### 방법 B - 로컬 HTTP 서버로 열기(`file://`에서 문제가 생길 때의 대안)
일부 크롬 버전/정책은 `file://`에서 더 엄격한 제한을 둘 수 있다. 문제가
있으면 아래처럼 아주 간단한 로컬 서버를 띄워서 `http://localhost:PORT/`로
접속한다(별도 설치 없이 파이썬이 있으면 바로 된다):

```bash
# 프로젝트 폴더 안에서
python3 -m http.server 8000
# 그 다음 크롬에서 http://localhost:8000/index.html 로 접속
```

Chromebook의 Linux(Crostini) 개발자 모드가 켜져 있다면 위 명령을 그대로
터미널에서 쓸 수 있다. Linux 모드가 없다면 방법 A(그냥 더블클릭)를
먼저 시도한다 - 대부분의 경우 그걸로 충분하다.

## 4. 실제로 검증한 것 / 검증하지 못한 것

이 프로젝트의 자동화 테스트는 이 저장소의 실제 소스 코드를 Node.js
`vm` 모듈로 직접 실행해 아이템/전투 로직의 정확성을 검증한다
(`docs/TESTING.md` 참고) - 이건 GLB 파일 없이도 가능하다. 반면
**헤드리스 Chromium 브라우저 테스트(이 환경 자체에 GLB 파일이 없어)는
상점 UI/아이템 상세 패널까지만 확인했고, 실제 챔피언을 불러와 기본
공격·스킬 시전·애니메이션까지 브라우저에서 직접 확인하지는 못했다** -
`docs/KNOWN_LIMITATIONS.md`에 이 한계를 명시해 뒀다. Chromebook에서 직접
GLB 파일을 불러와 플레이하면서 확인하는 절차가 필요하다.
